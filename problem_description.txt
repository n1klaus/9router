Fix two request-translation defects that make Claude-ecosystem requests fail or lose conversation turns. First: a request delivered to a Claude endpoint must never carry more than four cache_control markers. When the client has not spent its marker budget, the router still adds its own breakpoints on the last system block, the last cacheable tool, and the last assistant turn. Second: a conversation turn whose content is a single content block object, rather than an array, must be kept wherever messages are read or re-shaped: requests translated into Claude format, native Claude passthrough requests, and requests translated from Claude format into OpenAI format. Such a turn is delivered as a one-element array with any client-placed cache_control marker removed. Messages already using array content keep their structure and ordering. A request combining both defects — the marker budget spent and a single-object turn carrying a client marker — keeps the turn, normalizes it, removes its marker, and adds no marker past the four-marker limit.
